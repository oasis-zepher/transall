# Transall 译文复用与文档检查 · 2026-09-05

完成两项后续改进：排版失败时复用已完成译文，以及在整份 PDF 中定位问题、搜索文字和查看原文对照。变更继续位于 [草稿 PR #1](https://github.com/oasis-zepher/transall/pull/1)。

## 修改后的行为

| 场景 | 行为 |
|---|---|
| 保留版式翻译完成，但文字排不下 | 在排版前保存完整译文，失败后显示问题区域数量；不提供部分 PDF |
| 点击“查看问题区域…” | 打开提交时原文副本，自动定位并高亮第一处问题；列表显示页码、原文与完整译文，可切换区域 |
| 点击“生成纯译文 PDF” | 从本地缓存重新排版，不读服务密钥、不调用翻译处理器；沿用当前任务的完成凭据、预览、取消和保存规则 |
| 重启应用 | 在原有 24 小时保留期内恢复缓存；恢复任务仍只能另存为新文件 |
| 输入或缓存变化 | 拒绝导出；校验完整源文件 SHA-256、缓存内容摘要、版本、区域映射、语言、服务和术语表 |
| 取消或切换任务 | 等待旧任务停止后再显示恢复入口；旧异步读取不会填入新任务，旧输出清理不会删除新恢复结果 |
| 查看长 PDF | 页码输入、前后页、缩放；每侧独立搜索，显示匹配计数，支持前后匹配和清除 |
| 原文与结果页数相同 | 可按相同页码和页面位置联动，支持关闭 |
| 两侧页数不同 | 禁用同页联动并提示分别定位，避免把重新分页后的不同内容当作对应段落 |

缓存上限 32 MiB，私有原子写入，拒绝符号链接、硬链接缓存、非普通文件和读取中的变化；缓存与任务一起清理，不包含密钥或输入绝对路径。纯译文保留原文页顺序及页内区域提取顺序，各原文页从新页开始，长译文可以继续分页。

实际界面验收还修正了 `LocalizedError.recoverySuggestion` 的返回类型，使 Optional、NSError 和任务日志均保留正确的恢复建议。

## 限制

- 只复用已完成且通过校验的整份译文；未实现中断网络批次的续传。
- 纯译文会改变排版，可能增加页数；同页联动不是段落语义对齐。
- 搜索最多 2,000 处匹配、8 秒和 256 字符关键词，超过限制会给出提示。
- 仍未验证真实服务译文准确率、最低系统/Intel 实机、完整 VoiceOver 流程或签名上架。
- 先前 CI 的根因和修复见 [第一轮修复记录](2026-09-05-fixes.md)。推送已到达 GitHub，旧红色记录不会变绿；是否通过应查看 PR 最新提交的 Checks。

## 代码与回归

- `TranslationRecoveryTests.swift`、`TranslationRecoveryEngineTests.swift`、`DocumentInspectionTests.swift`：完整译文分页、损坏/替换/链接拒绝、不重复请求、取消/删除/重启、异步状态隔离、搜索与导航回归。
